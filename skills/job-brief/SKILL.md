# 채용 공고 브리핑

## 0. 준비 확인

- **사람인 MCP** — PlayMCP 도구함에 담긴 `SaraminMcp-search_saramin_jobs` 도구를 쓴다.
  안 보이면(`mcp__claude_ai_PlayMCP__SaraminMcp-search_saramin_jobs` 가 없으면) 멈추고,
  https://playmcp.kakao.com/mcp/1 에서 "사람인" 도구를 도구함에 추가하라고 알려 준다.
- **카카오톡 나챗방** 은 claude.ai 에 연결한 PlayMCP 커넥터의 `KakaotalkChat-MemoChat` 도구를 쓴다.
  이 플러그인은 `.mcp.json` 을 두지 않는다.

## 1. 데이터 — 사람인(saramin.co.kr), 세 직군 · 수도권 한정

아래 세 카테고리를 **순서대로** `search_saramin_jobs` 로 검색한다.
`locationCodes` 는 항상 `["101000", "102000", "108000"]`(서울·경기·인천, 즉 서울 근접
수도권)으로 고정한다 — 사용자가 출퇴근 기준으로 이 세 지역을 요청했기 때문이다.
그 외 배열 파라미터는 빈 배열 `[]`, 숫자 파라미터는 `0`, `recIds` 는 `""`,
`page`: `1`, `pageCount`: `10`, `sort`: `"Relation"`.

| 카테고리 | searchWord |
|---|---|
| 백엔드 개발자 | `백엔드 개발자` |
| 프론트엔드 개발자 | `프론트엔드 개발자` |
| AI/머신러닝 개발자 | `AI 엔지니어` (결과가 적으면 `머신러닝 엔지니어`, `컴퓨터비전`, `데이터 엔지니어`, `MLOps` 로 추가 검색) |

응답 위젯의 각 카드에서 공고 제목(`Text` 중 `weight: bold`인 값), 회사명, 지역(지역 Row의 두 번째
`Text`)을 그대로 뽑는다. 카테고리당 **상위 10개**를 쓴다.

규칙:

- 공고 제목·회사명·지역은 **도구가 반환한 것만** 쓴다. 기억이나 추정으로 채우지 않는다.
- 도구 호출이 에러를 내거나 결과가 0건이면 해당 카테고리는 `확인 못 함` 으로 적는다.
- (선택) 특정 회사가 궁금하면 `search_company_info` 로, 특정 지하철역 기준이면
  `search_subway_info` + `subwayCodes` 로 더 좁혀서 찾을 수 있다 — 이건 사용자가 회사명이나
  역명을 직접 말했을 때만 쓴다.

## 2. 터미널에 보여 주기

카테고리마다 10건을 번호로 모아서 보여 준다.

```
[채용 브리핑] 백엔드 개발자 · 2026-10-26 기준
1. (회사명) 공고 제목 - 지역
...
10. (회사명) 공고 제목 - 지역
출처: 사람인 saramin.co.kr
```

세 카테고리를 전부 출력한 뒤 3단계로 넘어간다.

## 3. 카카오톡 나챗방으로 보내기

- 카톡 도구는 메시지 **200자 제한**이 있어서, 10건을 한 메시지에 담을 수 없다.
  카테고리당 **5건씩 2개 메시지**(총 6개 메시지)로 나눠 `KakaotalkChat-MemoChat` 으로 보낸다.
- 각 메시지 첫 줄은 반드시 `[채용 브리핑] <카테고리명> <N>/2 · <날짜> 기준` 으로 시작한다
  (Hook 이 이 줄로 채용 메시지를 알아보고 날짜 유무를 검사한다).
- 회사명·제목 위주로 짧게 적고, 보내기 **전에 반드시 글자 수를 세어** 200자를 넘으면
  제목을 더 줄인다(예: 긴 수식어·영문 병기 삭제).

예시 (실제 전송 전 길이를 꼭 확인):

```
[채용 브리핑] AI/머신러닝 개발자 1/2 · 2026-10-26 기준
- (OOO) 컴퓨터비전 엔지니어 - 서울
- (OOO) 머신러닝 엔지니어 - 판교
- (OOO) ...
- (OOO) ...
- (OOO) ...
출처: 사람인
```

## 하지 말 것

- `무조건 합격`, `스펙 보장`, `100% 합격` 같은 **과장된 합격 보장** 말은 쓰지 않는다.
  Hook 이 이런 말이 든 카톡 전송을 막는다.
- 결과는 나만 본다. 사람인 홈페이지 내용은 허락 없이 옮기거나 퍼뜨리지 않는다.
- 세 카테고리 중 하나라도 공고를 못 읽었으면, 그 카테고리는 `확인 못 함` 이라고 보내고
  나머지 두 카테고리는 정상대로 보낸다 — 하나가 막혀도 전체를 건너뛰지 않는다.
- 한 카테고리의 두 메시지 중 하나가 200자를 넘어 막히더라도 나머지 한 메시지는 그대로 보낸다.
